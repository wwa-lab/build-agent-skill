# CodeCup 2026 中文交互路演

[打开 HTML 演示](codecup-2026.zh-CN.html) · [价值叙事与收益测量](../atlas-engineering-delivery-hub-build-pitch.md) · [POC 完整证据](../cases/rpgle-flow-poc/README.md)

18 页红、黑、白演示，按 Situation → Solution → Result 展开。没有倒计时或自动翻页，讲述者可自由选择节奏。标题、文字、图示和讲稿都可在 HTML 中继续编辑。

## 使用

下载或克隆仓库后，用现代浏览器打开 `codecup-2026.zh-CN.html`。单个文件包含全部内容、样式和交互脚本；播放不需要安装依赖或连接网络。点击 GitHub 原始证据链接时需要联网。GitHub 文件页展示源码，不直接播放 HTML。

也可以在仓库根目录启动本地预览：

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

然后打开 [本地演示](http://127.0.0.1:8765/docs/presentations/codecup-2026.zh-CN.html)。可用 `#slide-12` 直接定位第 12 页。

| 操作 | 用法 |
| --- | --- |
| 翻页 | 左右 / 上下方向键、PageUp / PageDown、底部箭头、滚轮或触屏滑动 |
| 空格 | 下一页；Shift + 空格上一页。按钮获得焦点时保留原生按钮操作 |
| 首尾页 | Home / End |
| 目录 | O 或底部“目录”，点击标题跳转 |
| 讲稿 | N 或底部“讲稿”，显示当前页讲述提示 |
| 全屏 | F 或底部“全屏”；不支持时显示浏览器菜单提示 |
| 关闭弹窗 | Esc 或“关闭” |

系统设置减少动态效果时，演示会缩减入场和切换动画。目录与讲稿在当前屏幕显示，观众也能看到；当前不提供独立讲者窗口。

## 内容与交互

| 页码 | 内容 | 讲述重点 |
| --- | --- | --- |
| 1–2 | 开场与定位 | 企业级 SDD：企业问题、实践方法、领域实现 |
| 3–5 | Situation | 四个交付问题、首个 IBM i Pilot 反馈、重复投入 |
| 6–10 | Solution | 按范围选路径、领域约定、检查依据与人工确认 |
| 11–13 | IBM i POC | 订单履约案例、BR-06 五层证据、具体修正 |
| 14–16 | Result | 已有静态证据、待验证项、实际收益测量 |
| 17–18 | 下一步 | 新技术场景适配、真实案例验证 |

第 7 页可切换三类变更路径；第 9 页可展开阶段说明；第 10 页可演示“依据缺失 → 补充资料 → 人工确认”；第 12 页可切换需求、规格、文件、源码和静态检查证据。

演示定位为企业级 SDD 交付实践，IBM i 是首个深入实践场景；当前没有第二技术场景的已验证实现。路径和人工确认交互是讲解示意，不调用 Agent、模型或 IBM i。POC 为合成案例，产物为 Draft；没有编译、业务执行、模型评测和实际效率收益记录。源码摘录压缩了固定格式列宽，原始源码通过链接查看。

## 内容维护

价值主张以 [pitch 文档](../atlas-engineering-delivery-hub-build-pitch.md)为维护入口，演示只做视觉化表达。改动主张时先核对证据，再同步对应页及其 `data-note` 讲稿。

案例与技能证据链接固定到仓库提交 `2b853130eb2032d8204e9abfda5564c9efa48f78`，避免后续 main 变化影响本版引用。价值叙事链接指向同一工作区的最新 pitch 文档，包含当前定位与扩展路线。新增真实案例时使用[案例模板](../cases/case-template.md)，记录来源、实际执行层级和测量结果，再更新演示中的结果主张与链接版本。

## GitHub 方案调研

- [reveal.js](https://github.com/hakimel/reveal.js)：成熟的 HTML 演示框架，适合后续需要丰富插件和讲者视图时评估。
- [Slidev](https://github.com/slidevjs/slidev)：以 Markdown 与 Vue 组织交互演示，适合持续组件化开发。
- [frontend-slides](https://github.com/zarazhangrui/frontend-slides)：采用可独立打开的 HTML 演示思路，贴合本仓库以文档为主、方便交接的需要。

本版使用独立 HTML 实现，没有引入上述框架运行依赖。动画用于表达信息层次，流程交互用于解释机制。
